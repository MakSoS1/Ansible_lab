## LLM weak-label conclusion

`matches_llm.parquet` has `11,187,780` rows but exact human-pair overlap `0`. Existing weak labels therefore do not have measured class precision against trusted truth. Current new-architecture candidates admit **zero LLM-labelled rows**.

A6 is explicitly different from legacy weak supervision: its Arrow reader requests only `id1,id2` from the retrieval graph; the old `target` column is never loaded. Soft targets are regenerated by fold-safe human-trained neural + structured teachers, and candidate items overlapping the complete human universe are excluded.

## v14 architectural conclusion so far

A0/A1/A3 make one point clear: replacing the CrossEncoder with an independent bi-encoder/MaxSim scorer destroys too much pair-specific information, and sampler/MoE/ranking tweaks do not restore it. The active v14 direction therefore keeps item-local reusable encoding but reintroduces **cheap pair-conditioned reasoning after compression**:

`unique item -> item/token encoder -> 12 reusable slots -> tiny bidirectional cross-attention -> symmetric category-conditioned score`.

A5 tests this with ruBERT; A8 tests it with a compact retrieval-pretrained Granite encoder; A12 additionally injects typed product-attribute conflicts into the learned head.

## Runtime rule

The intended new runtime encodes each unique product once, caches its compact representation, then scores pairs with a very small cross-attention block. Any promoted candidate still has to pass the exact organizer-shaped `<60 s` Check on final ZIP bytes. Quality alone is insufficient.
