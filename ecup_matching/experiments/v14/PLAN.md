# E-CUP v14 — genuinely new item-centric architecture plan

Status: **in progress — structural screening**

## Why v14 exists

v13 B improved the local fold0 score while regressing on the real Public LB:

- v12 fold0 Macro AP: `0.7059297810308699`
- v12 Public LB: `0.3798116204`
- v13 B fold0 Macro AP: `0.7086611385531062`
- v13 B Public LB: `0.3783781653`
- Public delta `v13 - v12 = -0.0014334551`

The exact v13 archive was runtime-valid, so the regression is a distribution/model-selection failure rather than a crash. v14 therefore does **not** continue weak-sampler micro-tuning of the same full pair CrossEncoder.

The previously built v12 category-gated residual remains reproducible and runtime-safe, but it is now a **superseded technical fallback**, not the requested v14 architecture.

## LLM-label gate

The legacy weak file contains `11,187,780` rows, but exact pair overlap with trusted human labels is `0`. Its class-label precision cannot therefore be measured from the existing corpus.

Rules for v14:

1. A0/A1/A3/A5/A8/A10/A12 use **zero LLM-labelled rows**.
2. Self-reported LLM confidence is not treated as reliability evidence.
3. A6 may use the weak **retrieval graph only**: its Arrow reader requests `id1,id2` and does not read the legacy `target` column.
4. A6 soft targets are regenerated by fold-safe human-trained neural and structured teachers.
5. LLM labels can return only after a separate human-stratified audit demonstrates a real benefit.

## Architectural hypothesis

A pure bi-encoder/MaxSim replacement is too weak because product matching requires pair-conditioned reasoning about exact models, variants, capacities, sizes and attributes. A full concatenated CrossEncoder is strong but recomputes the entire Transformer for every pair.

The main v14 architecture therefore splits the computation:

```text
item A -> shared encoder -> reusable token/item representation -> learned compact slots -\
                                                                           -> tiny pair cross-interaction -> score
item B -> shared encoder -> reusable token/item representation -> learned compact slots -/
```

The expensive encoder runs independently per unique item and can be cached. Pair-conditioned reasoning is restored only after compression.

## Active candidate ladder

### A5 — ruBERT compressed cross-interaction

Architecture:

- shared ruBERT item encoder;
- global/title/attribute vectors retained;
- token projection compressed to `12` reusable learned slots per item;
- small shared bidirectional cross-attention over the two slot sets;
- symmetric interaction features and category-conditioned expert residual;
- BCE + category-local ranking + human positive-component SupCon;
- item encoding cached once for held/runtime scoring.

A5 is the minimum viable new architecture because it reintroduces pair-conditioned reasoning without returning to a full pair Transformer.

### A8 — Granite-97M compressed cross-interaction

Same matcher with pinned retrieval-pretrained multilingual encoder:

- model: `ibm-granite/granite-embedding-97m-multilingual-r2`
- revision: `c61e626a6255c490879d0af885078b61929d51f6`
- weights SHA-256: `f3ea88b230492811046145513710e76b4cc8c2ad49e8708da0e7247e548903be`

ModernBERT implicit TorchInductor/Triton compilation is explicitly disabled (`reference_compile=false`) in screen, production and submission runtime. Compiler/cache paths are additionally constrained to writable `/tmp`.

### A12 — Granite compressed cross + typed product features

If A5/A8 do not recover enough quality, fuse fold-safe typed `features_v2` into the neural pair head:

- model-code match/conflict;
- number/quantity match/conflict with canonical units;
- brand match/conflict;
- same-key attribute agreement/conflict;
- attribute-key overlap;
- fuzzy/title lexical similarity.

Category-specific attribute importance is learned **only from the training side of the current fold**. A12 is still human-only.

### A6 — LLM-free retrieval-domain distillation

A6 addresses a different problem: human-only pair distribution may not match the retrieval-heavy test distribution.

- weak parquet supplies candidate pair IDs / retrieval groups only;
- legacy weak target is never read;
- every item appearing anywhere in human truth is excluded from the distill candidate pool;
- a human-only fold-safe neural teacher and structured teacher generate soft targets;
- A5 is warm-started, receives a short distillation phase, then a clean human recovery phase;
- inference remains one compressed-cross student.

### A10 — stronger multilingual encoder reserve

If compact Granite is the capacity bottleneck, test pinned `intfloat/multilingual-e5-base` under the same compressed-cross head. Synthetic 0/1 pair-field token types are used only to construct field masks and are not forwarded into XLM-R embeddings.

### Setwise teacher reserve

A candidate-set Transformer without positional encodings is available as an **offline teacher** to model competition among candidates around the same retrieval anchor. It must earn held-fold evidence before distillation and is not required at final inference.

## Fold0 promotion gate

Novelty is not sufficient. Before paying the cost of five-fold confirmation, a candidate must recover to a credible quality region relative to the v12 fold0 reference `0.7059297810308699`.

If a candidate remains near the A0/A1 `~0.54–0.55` range, it is rejected even if technically elegant. Continue A12/A6/A10/setwise rather than package a weak model.

## Strict OOF gate for a promoted candidate

For the selected architecture:

1. reuse immutable fold0 evidence;
2. train folds `1–4` with exactly the same model/training contract;
3. aggregate exactly `285210` unique development rows once;
4. require fold IDs `{0,1,2,3,4}` and no duplicate/missing row indices;
5. require zero train/held item overlap and zero sealed-gold scoring;
6. record overall Macro AP, per-category AP and per-fold robustness.

Do not tune the architecture after looking at the strict aggregate without starting a new declared experiment.

## Production refit

A selected standard compressed candidate is retrained on the full `285210` development rows only. The sealed `80444` rows remain untouched.

Production checkpoint must contain:

- one encoder + compressed interaction model state;
- 20 categories;
- exact architecture dimensions;
- pinned base-model identity/revision/hash where applicable;
- no raw competition rows or OOF predictions.

## Submission runtime

Intended runtime:

```text
read requested pair IDs
-> materialize requested items
-> encode each unique item once
-> keep reusable compact item cache
-> score pair batches with tiny cross-attention
-> write id1,id2,predict
```

No network is allowed. ModernBERT implicit compilation is disabled to avoid compiler startup/cache behavior in the organizer container.

## Binding package gate
