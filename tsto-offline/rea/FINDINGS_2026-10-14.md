# The Simpsons: Tapped Out 4.69.5 — REA analysis (2026-10-14)

## Evidence

GitHub Actions run [38483164588](https://github.com/MakSoS1/Ansible_lab/actions/runs/38483164588) collected APK, ELF and REA package analysis. Second run [38483425681](https://github.com/MakSoS1/Ansible_lab/actions/runs/38483425681) inspected the concrete lifecycle methods. Both runs were successful; only reports, not copyrighted game binaries, were uploaded.

APK source was an archived copy in bodnjenie14/Tsto_patcher, `Original Files/tsto_original.apk`. SHA256 of APK is `ba07b9c6e3bd20623508c53f0b079445f2036517ef5e01f27aa71adf81c98079`. APK version 4.69.5, versionCode 695, package `com.ea.game.simpsons4_row`, targetSDK 34. Real decompilation covered 5,268 parsed classes. Four Scorpio ARM64/ARMv7 libs exactly matched the supported hashes in TappedOutReborn/Patch-Apk. ARM64 Scorpio and C++ shared libraries reported PT_LOAD alignment 4096, not 16384. Pixel 10 Android 16 runtime compatibility has **not** been established.

## REA/JADX lifecycle observations (not runtime tests)

`com.ea.game.simpsons4_row.SimpsonsApplication.onCreate()`: registers a notification channel, receives Nimble/PushTNG setup notifications, reads manifest metadata, calls `super.onCreate()`, stores a singleton, attempts `setupTelemetry()` and calls `AppCenterJava.Reset(this)`. This is the earliest well-defined application lifecycle hook for starting an *already packaged* local service. **An actual server bootstrap is not implemented.**

`com.ea.simpsons.SimpsonsSplashScreen.onCreate(Bundle)`: initializes immersion/orientation, `GetManifestData`, updates `NetworkStatus`, and then launches `new PreloadTask().execute(new Void[0])`. The preload task can race with a server start. A proposed dependency check should gate the preload phase, rather than sleep on the main thread.

`com.ea.simpsons.SimpsonsActivity.onCreate(Bundle)`: checks `libNimble.so`, reloads engine libraries if needed, starts Facebook SDK and AndroidFacebookManager, constructs ScorpioAndroidInfo, gets the installed package version, runs `doOnCreate()`, and registers Android lifecycle callbacks.

## Proposed integration (not implemented)

1. Build and verify an Android-ABI-compatible local server using *redistributable* source (GameServer-Reborn GPLv3, or a separately licensed rewrite) and its required SQLite/protobuf dependencies. Bind solely to loopback on an unprivileged port; use app-private storage for town saves.
2. Start the service from the application lifecycle, make its readiness check asynchronous with a bounded startup timeout; only proceed with `PreloadTask` when the server is actually ready. No background daemon after game process exit.
3. Patch both director/game endpoints and native DLC URL logic of the **specific hash-matched** client. Localhost URL acceptance is still unverified; a string replacement in a native ELF is not enough on its own.
4. Establish a complete dependency closure for `ru` and `en` DLC and required common tiers; deleting other languages before verifying all asset references risks failure. Report actual size before deciding on a single file vs app-internal extraction.
5. Test real startup, tutorial, saves/restart, airplane mode, time-dependent events, Android 16 storage constraints, and 16-KiB native-loader behavior on Pixel 10, including profiling CPU/RAM/battery.
6. Only then sign the installable APK using a test or private key and validate that the same APK contains both client and server, and works without fetching any remote files.

## Important status

The two investigative GitHub Actions jobs **did not build a functional unified game APK**. No APK or EA DLC are in this public repo. Shutdown of EA online services does not grant a license to publicly redistribute the proprietary game and artwork. This research concerns binary interoperability and local single-player preservation.
